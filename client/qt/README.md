# QT 监控客户端

该目录是 Windows QT 客户端工程，目标开发环境为 Qt 5.14.2 和 Qt Creator 4.11.1。客户端使用 C++11，协议采用服务端统一的 TLV 格式，默认连接云服务器 `106.55.9.115:7777`。

## 当前功能

- 输入系统用户名和密码登录；
- 注册系统用户；
- 登录成功后在同一 TCP 连接请求摄像头列表；
- 双击摄像头或点击“查看实时画面”，先请求摄像头信息，再使用返回的 RTSP 地址播放；
- 停止播放、刷新列表和退出登录；
- 连接、协议和播放错误在界面状态栏显示。

## 使用 Qt Creator 编译

1. 在 Qt Creator 中打开 `QtClient.pro`。
2. 选择 Qt 5.14.2 的 32 位 Kit（MinGW 32 位或 MSVC x86），不要选择 64 位 Kit。
3. 构建并运行。生成文件位于 `client/qt/bin/`。

## 部署 libVLC

实时 RTSP 播放使用 libVLC 动态加载，不需要在 `.pro` 中绑定 VLC 的导入库。客户端和 VLC 必须使用相同的 32 位架构。

将 32 位 VLC 运行库中的以下内容复制到 `client/qt/bin/`，与 `SmartHomeClient.exe` 放在一起：

```text
libvlc.dll
libvlccore.dll
plugins/
```

如果运行时提示找不到 `libvlc.dll` 或 `plugins`，说明 VLC 运行库没有部署完整。VLC 播放器的版本应与所复制的 DLL 保持一致。

## 云服务器准备

服务端需要监听外部连接。`conf/server.conf` 默认已经设置为：

```text
ip 0.0.0.0
port 7777
```

云服务器安全组和 Ubuntu 防火墙需要放行 TCP `7777`。服务端启动后确认：

```bash
ss -ltnp | grep ':7777'
```

然后在 QT 客户端登录页使用：

```text
服务端地址：106.55.9.115
服务端端口：7777
```

服务端必须先配置 `SHMS_DB_*` 环境变量并启动成功，用户和摄像头业务才会启用。用户注册后再使用相同账号登录。

## 摄像头网络要求

服务端返回的是摄像头的 RTSP 地址，视频流由 QT 客户端直接连接摄像头播放。因此，Windows 客户端必须能够访问摄像头的 `192.168.2.x` 地址：

- Windows 与摄像头在同一局域网；或
- Windows 已通过 VPN、专线或路由能够访问 `192.168.2.0/24`；或
- 摄像头 RTSP 服务通过端口映射提供了 Windows 可访问的地址。

仅仅能够访问云服务器 `106.55.9.115`，不能自动访问 `192.168.2.100` 和 `192.168.2.160`。如果客户端无法访问摄像头内网，登录和摄像头列表仍可正常工作，但实时画面会连接失败。

摄像头信息需要写入云服务器数据库的 `t_camera` 表，RTSP 地址中的摄像头账号密码不要提交到 Git 仓库或公开日志中。
